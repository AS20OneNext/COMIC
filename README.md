# COMIC — دوبله و ترجمهٔ زنده برای اندروید

**COMIC** یک برنامهٔ بومی اندروید برای دریافت صدای پخش‌شده از برنامه‌های سازگار و ترجمه/دوبلهٔ زندهٔ آن با استفاده از **Gemini Live** است. خروجی صوتی ترجمه‌شده مستقیماً در برنامه پخش می‌شود.

> **وضعیت پروژه: آزمایشی** — نسخهٔ تعریف‌شده در Gradle برابر `0.2-experimental` است. این مخزن به معنی انتشار نسخهٔ پایدار یا تضمین سازگاری با همهٔ برنامه‌ها و دستگاه‌ها نیست.

## قابلیت‌ها

- دریافت صدای پخش‌شده از برنامه‌های دیگر اندروید با `MediaProjection` و `AudioPlaybackCapture`، پس از تأیید مجوز سیستمی کاربر.
- انتخاب یک برنامهٔ مشخص یا دریافت صدای تمام برنامه‌های واجد شرایط.
- ارسال صدای ورودی به مدل `gemini-3.5-live-translate-preview` از طریق اتصال WebSocket سرویس Gemini Live.
- دریافت و پخش پیوستهٔ صدای ترجمه‌شده.
- انتخاب زبان مقصد از میان ۱۲ زبان تعریف‌شده در برنامه؛ فارسی زبان مقصد پیش‌فرض است.
- رابط کاربری انگلیسی به‌صورت پیش‌فرض در نصب تازه و امکان تغییر زبان رابط به فارسی.
- پوستهٔ روشن، تیره و حالت پیروی از تنظیم سیستم.
- ذخیرهٔ کلید API واردشده توسط کاربر با رمزنگاری AES-256-GCM و نگهداری کلید رمزنگاری در Android Keystore.

## دریافت و آماده‌سازی

مخزن را Clone کنید:

```bash
git clone <REPOSITORY_URL>
cd COMIC
```

سپس مطمئن شوید Gradle نسخهٔ `9.3.1` و JDK نسخهٔ `17` یا بالاتر در PATH سیستم در دسترس هستند. برای بررسی:

```bash
java -version
gradle --version
```

> **نکتهٔ مهم دربارهٔ Gradle Wrapper:** فایل `gradle/wrapper/gradle-wrapper.properties` در پروژه وجود دارد، اما فایل‌های اجرایی Wrapper (`gradlew`، `gradlew.bat` و `gradle-wrapper.jar`) در نسخهٔ تحویلی موجود نیستند. به همین دلیل، راهنمای محلی و گردش‌کار GitHub Actions فعلاً از Gradle نصب‌شده با نسخهٔ ثابت `9.3.1` استفاده می‌کنند؛ از اجرای `./gradlew` انتظار نداشته باشید تا زمانی که Wrapper رسمی به مخزن اضافه شود.

## ساخت و بررسی پروژه

دستورها را از ریشهٔ مخزن اجرا کنید:

```bash
# ساخت APK آزمایشی (Debug)
gradle --no-daemon :app:assembleDebug

# اجرای تست‌های واحد و Robolectric
gradle --no-daemon :app:testDebugUnitTest

# اجرای Android Lint
gradle --no-daemon :app:lintDebug

# اجرای همهٔ بررسی‌های بالا در یک فراخوانی
gradle --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

فایل APK نسخهٔ Debug پس از ساخت در مسیر زیر قرار می‌گیرد:

```text
app/build/outputs/apk/debug/app-debug.apk
```

در GitHub Actions همین تست‌ها و بررسی Lint اجرا می‌شوند و در صورت موفقیت، APK آزمایشی به‌عنوان Artifact همان اجرای Workflow بارگذاری می‌شود.

## کلید Gemini و تنظیمات اجرا

1. برنامه را روی دستگاه اجرا کنید.
2. کلید API شخصی Gemini را در صفحهٔ خوش‌آمدگویی وارد کنید یا بعداً از بخش تنظیمات ثبت کنید.
3. اتصال را با گزینهٔ تست اتصال بررسی کنید.
4. زبان مقصد و منبع صدا را انتخاب کنید.
5. مجوزهای اندروید، از جمله ضبط صدای پخش‌شده و Media Projection، را در پنجره‌های سیستمی تأیید کنید.

**کلید API را در سورس، فایل‌های تنظیمات، Issue، Pull Request یا تاریخچهٔ Git قرار ندهید.** کلید در برنامه با Android Keystore رمزنگاری می‌شود، اما این ویژگی جایگزین مدیریت امن کلید در حساب Google یا رعایت محدودیت‌های سرویس نیست. درخواست‌های ترجمه برای پردازش به سرویس Google ارسال می‌شوند.

### ساخت نسخهٔ Release

پیکربندی Release موجود از متغیرهای محیطی زیر استفاده می‌کند:

- `KEYSTORE_PATH` — مسیر فایل keystore؛ در صورت تنظیم‌نشدن، مسیر پیش‌فرض `my-upload-key.jks` در ریشهٔ پروژه در نظر گرفته می‌شود.
- `STORE_PASSWORD` — رمز keystore.
- `KEY_PASSWORD` — رمز کلید.

نام alias در پیکربندی فعلی `upload` است. فایل keystore و رمزها را هرگز به Git اضافه نکنید. برای انتشار واقعی، کلید امضای اختصاصی خود را خارج از مخزن نگه دارید و مقادیر لازم را در محیط امن سیستم CI تنظیم کنید. Workflow فعلی فقط نسخهٔ Debug را می‌سازد و Release را منتشر نمی‌کند.

## محدودیت‌های مهم اندروید

- فقط صدای برنامه‌هایی قابل دریافت است که سیاست ضبط صدای پخش‌شدهٔ اندروید را مجاز کرده باشند. برنامه‌های محافظت‌شده، محتوای DRM یا برنامه‌هایی که ضبط را مسدود می‌کنند ممکن است صدایی در اختیار COMIC قرار ندهند.
- دریافت صدا به تأیید کاربر از طریق پنجرهٔ سیستمی Media Projection وابسته است و با لغو مجوز باید متوقف شود.
- اندروید امکان بی‌صدا یا کم‌کردن مستقل صدای برنامهٔ مبدأ را در اختیار COMIC قرار نمی‌دهد. برای شنیدن صدای دوبله‌شده، از کنترل صدای برنامهٔ مبدأ یا دستگاه و کنترل حجم خروجی COMIC استفاده کنید.
- رفتار واقعی ضبط صدا، تأخیر، مسیر‌دهی هدفون و سازگاری برنامه‌های مبدأ باید روی دستگاه فیزیکی آزمایش شود.
- مدل Live استفاده‌شده در پروژه یک مدل Preview است؛ دسترسی، شرایط استفاده و نام/رفتار مدل ممکن است از سوی ارائه‌دهنده تغییر کند.

## تست‌ها

مخزن شامل تست‌هایی برای پردازش PCM، تنظیمات برنامه، پیکربندی و پیام‌های Gemini Live، جریان WebSocket، مدیریت وضعیت دوبله و برخی تعاملات رابط کاربری با Robolectric است. تست‌ها با دستورهای بخش «ساخت و بررسی پروژه» اجرا می‌شوند.

آزمون‌های وابسته به سخت‌افزار و محیط واقعی — از جمله ضبط صدای برنامه‌های دیگر، کیفیت خروجی، تأخیر، بلوتوث و لغو Media Projection — باید جداگانه روی دستگاه واقعی انجام شوند. موفقیت تست‌های واحد به‌تنهایی تأییدکنندهٔ عملکرد کامل دوبله در همهٔ دستگاه‌ها نیست.
